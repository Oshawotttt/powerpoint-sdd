description: Optionally save where a repo's PowerPoint files live, by creating the folders, writing the map into the repo, and optionally gitignoring the folders. The other ppt- skills work without it.
argument-hint: "[--dir folder]"

---

Save a PowerPoint map into the repo, so the other `ppt-` skills stop asking where the files live. The skills work without it: they ask for a folder and use the default paths in the template below.

**Repo root:** `git rev-parse --show-toplevel`, or the working directory outside git.

**Base folder:** the `--dir <folder>` argument, relative to the working directory. Otherwise the repo root.

The root folders are `SPEC_DIR`, `OUTPUT_DIR` and `CONTEXT_DIR`. Their default paths are in the template's table, relative to the base folder.

## 1. Inspect

- **Earlier init:** a map already exists if `CLAUDE.md`, `MAP.md`, or a file `CLAUDE.md` points to has a `PowerPoint map` heading. Keep the paths the map uses and treat its folders as yours. Update that map in place in step 5.
- **Overlaps:** list every root folder default that already exists in the base folder and is not yours from an earlier init. Compare names case-insensitively, and count a file of the same name as an overlap.
- **`CLAUDE.md`:** count its lines.

## 2. Ask

Ask these together with `AskUserQuestion`. Skip a question that has nothing to settle.

- **Each overlap:** which name to use instead. Offer `ppt-<name>/` as the suggestion and sharing the existing folder as the alternative. The user may type their own name. Check that any new name is free too, and ask again if it is taken.
- **Gitignore:** whether to gitignore the PowerPoint folders. Their contents would then exist only on this machine.

The step is complete when every root folder has a name that is free or that the user chose to share.

## 3. Create the folders

Create each root folder under its settled name. Leave the contents of existing folders untouched.

## 4. Gitignore

If the user said yes, add each root folder to the repo's `.gitignore` as its path from the repo root with a trailing `/`, creating the file if needed. Append only entries that are missing, and keep the existing lines.

Leave out any folder the user chose to share, because ignoring it would hide their existing files. Name the left-out folders in the report.

## 5. Write the map

Build the map from the template below. Rewrite each path in the table from the repo root: put the base folder in front when it is not the repo root, and change every path under a renamed root folder. Keep any path an earlier map already sets. Include the gitignore paragraph only if step 4 added folders, naming only those folders.

Replace an earlier map where it is. Otherwise, where the map goes depends on `CLAUDE.md` at the repo root:

- **Missing:** create `CLAUDE.md` with a `# <repo name>` heading, then the map.
- **100 lines or fewer:** add the map as a new section at the end.
- **More than 100 lines:** write the map to `MAP.md` at the repo root, then add this one line to `CLAUDE.md`:

  ```markdown
  For any PowerPoint-related feature, view the map in `MAP.md`.
  ```

  If `MAP.md` already exists and is not the map from an earlier init, ask the user for another file name and use it in the line.

Template, with `#` in place of `##` when it is the whole of `MAP.md`:

````markdown
## PowerPoint map

Spec-driven PowerPoint decks: draft the deck in `SPEC_DIR`, then build the deck into `OUTPUT_DIR`.

Skills refer to files by the names below. To move a file, change its path here. Paths are relative to the repo root. The folders hold one deck.

| Reference | Path | Use |
|---|---|---|
| `SPEC_DIR` | `spec/` | The deck's spec. `/ppt-spec` creates it. |
| `ARCHITECTURE_FILE` | `spec/ARCHITECTURE.md` | Overall outline that joins the sections: Brief, design system, section statuses. `/ppt-spec` writes it, `/ppt-layout` updates it, `/ppt-draft` and `/ppt-generate` read it. |
| `SECTION_FILE` | `spec/<section>.md` | Draft of one section, one file per section. `/ppt-spec` writes it, `/ppt-layout` adds layouts, `/ppt-draft` and `/ppt-generate` read it. |
| `FULL_FILE` | `spec/FULL.md` | The whole spec in one file: `ARCHITECTURE_FILE`, then every `SECTION_FILE`. Generated by `/ppt-combine`, so edit the files it is built from instead. Not a section file. |
| `RESOURCE_DIR` | `spec/resources/<section>/` | Pictures and draft graphs used by that section. `/ppt-spec` fills it, `/ppt-draft` and `/ppt-generate` place them. |
| `GRAPH_DIR` | `spec/resources/<section>/<graph-name>/` | One draft graph with its data and script. `/ppt-spec` creates it, `/ppt-draft` and `/ppt-generate` redraw from it. |
| `DRAFT_FILE` | `spec/drafts/<section>-slide-<n>-<descriptor>.html` | HTML draft of one slide. `/ppt-draft` writes it, `/ppt-generate` follows its arrangement. |
| `OUTPUT_DIR` | `output/` | The finished deck and its build script. |
| `DECK_FILE` | `output/<deck>.pptx` | Finished PowerPoint file, where `<deck>` is the base folder's name in kebab-case. `/ppt-generate` writes it. |
| `BUILD_SCRIPT` | `output/build/build.js` | Script that generates the deck. `/ppt-generate` writes and reruns it. |
| `CONTEXT_DIR` | `context/` | All cloned repos. `/ppt-spec` searches it for facts. |
| `CONTEXT_REPO_DIR` | `context/<repo>/` | One cloned repo, for reference when drafting. `/ppt-spec` clones into it. |

`<section>` is the section's number in `ARCHITECTURE_FILE` as two digits, a hyphen, and its name in kebab-case, such as `01-problem`, so files sort in presentation order.

Skills: `/ppt-spec` creates a spec through discussion. `/ppt-layout` assigns a design system's layouts to the spec's slides. `/ppt-draft` drafts the hardest slides in HTML. `/ppt-generate` builds the deck from an approved spec and a design system. `/ppt-combine` writes the whole spec into `FULL_FILE` to read in one place.

<gitignored folders> are gitignored, so their contents exist only on this machine. Ripgrep-based search skips them by default; pass `--no-ignore` or target the path directly.
````

## 6. Report

Name the base folder, the folders created, any renamed or shared folders, the file that holds the map, and the `.gitignore` entries added. Leave the changes uncommitted.
